## 2. Frontend Workspace UI & Positioning Layout

Split-screen viewports (1:1 ratio) desktop layout:

* **Left Pane (Reference):** Render original untranslated PDF as a static canvas via `pdf.js`.
* **Right Pane (Interactive Canvas Layer):** * **Base Layer:** Render PDF background page (images/lines only) via `pdf.js`.
* **Overlay Layer:** A transparent, absolute-positioned HTML container layered exactly over the base layer.
* **Positioning Formula for Input Fields (`div[contenteditable]`):**

$$\text{left} = x_0, \quad \text{top} = y_0, \quad \text{width} = x_1 - x_0, \quad \text{height} = y_1 - y_0$$

## 3. Core Algorithm: Dynamic Font Downsizing & Collision Detection

To prevent layout overlapping ("box-bursting"), enforce this execution loop on the frontend `input` event:

```
[User Types Text] ──► [Sync to Hidden <span>] ──► [Measure Width/Height via DOM]
                                                           │
  ┌─────────────────── [Font Size -= 0.5pt] ◄── [Overflow Detected?] 
  │                                                        │
  ▼                                                        ▼ (No)
[Render Safely]                                      [Keep State]

```

### 3.1 Execution Logic

1. **Target Boundaries:** $W_{max} = x_1 - x_0$, $H_{max} = y_1 - y_0$.
2. **Measurement:** Mirror the active text into a hidden off-screen `<span>` with `visibility: hidden` matching the current font style. Measure via `span.getBoundingClientRect()`.
3. **Loop Condition:** * **WHILE** $\text{Measured Width} > W_{max}$ OR $\text{Measured Height} > H_{max}$:
* Decrement CSS `font-size` by `0.5pt`.
* Update `font_size_current` in JSON state.
4. **Safety Fuse:** IF `font_size_current` < `8pt` AND text still overflows, trigger a UI error state (`border: 1px solid red`) and flag a warning to the user to manually shorten the text string.

## 4. Save & Backend Re-rendering Pipe

### 4.1 Save Payload to Backend

```json
{
  "status": "validated",
  "payload": [
    {
      "block_id": "b_001",
      "tgt_text": "User edited text string...",
      "font_size_final": 10.5
    }
  ]
}

```

### 4.2 Backend Re-draw Protocol

1. Read the finalized payload.
2. Initialize **BabelDOC / PyMuPDF** engine instance.
3. For each block, execute pixel-level bounding box erase based on `rect`.
4. Draw `tgt_text` strictly inside `rect` applying `font_size_final`. Output finalized PDF.

## 5. Robustness Enhancements for Industrial Datasheets (Edge Cases)

### 5.1 Backend Layout De-duplication & Merging (Anti-Overlap)
Before sending the JSON to the frontend, the backend must clean and cluster fragmented bounding boxes to prevent overlapping boxes generated by PDF text segmentation.
* **Algorithm:** If two or more blocks on the same page have an Intersection over Union (IoU) ratio > 0.3, or if their vertical distance is within 5 pixels, the backend MUST merge their rectangles into a single, combined $rect$ enclosing both blocks.
* **Text Aggregation:** Concatenate the corresponding text segments in the logical reading order before passing them to the LLM Translation API.

### 5.2 Frontend Render Masking (Forced Erasing Layer)
To prevent original untranslated "ghost characters" from peeking through from the PDF base layer:
* **UI Spec:** The frontend interactive edit box MUST NOT have a transparent background. 
* **Style Constraint:** Set the editing box CSS to `background-color: #FFFFFF !important; z-index: 10;`. This acts as a physical solid mask to completely blind out the background vector texts.

### 5.3 Font & Character Sanitization (Fixing Unknown Glyphs "□")
Industrial documents contain dense technical symbols (e.g., `~`, `×`, `°C`). 
* **Backend Sanitizer Rule:** Pre-process raw extracted strings using a Regex filter. Map non-standard custom font glyphs to standard Unicode entities before translation:
  * Replace unknown spacing blocks with standard spaces ` ` or hyphens `-`.
  * Replace malformed multiplication tokens with standard `×`.
* **Frontend Font Family Fallback:** Force custom CSS font stack to ensure absolute compliance with technical symbols:
  ```css
  div[contenteditable] {
      font-family: "Courier New", Arial, "SimSun", "Microsoft YaHei", sans-serif;
  }
  ```

## 6. Advanced Table Structure Recognition (TSR) & Matrix Alignment

### 6.1 Backend Table Cell Grid Clustering
The backend MUST NOT treat table text as isolated blocks. It must detect the structural matrix of tables using Table Structure Recognition (TSR) models (e.g., PaddleOCR-Table or TableTransformer).
* **Grid Mapping:** For every table detected within a master bounding box ($rect_{table}$), the backend must generate a structured cell matrix mapping rows and columns.
* **Cell Schema Specification:**
  ```json

    "type": "table",
    "table_rect": [50.0, 300.0, 550.0, 500.0],
    "rows_count": 5,
    "cols_count": 4,
    "cells": [
      {
        "cell_id": "c_r1_c1",
        "row_index": 1,
        "col_index": 1,
        "rect": [50.0, 300.0, 150.0, 340.0],
        "src_text": "Analog input current",
        "tgt_text": "模拟输入电流"
      }
    ]
  }
  ```
### 6.2 Frontend Layout: CSS Grid Vector Injection

To prevent vertical misalignment and floating text bugs inside tables:
* UI Implementation: The frontend MUST render a native HTML <table> or a CSS Grid container wrapped exactly inside the table_rect absolute boundaries. Do not use absolute positioning for individual cells.
* Layout Constraints: * Set table-layout: fixed; width: 100%; height: 100%; to force cells to stay strictly within the detected column widths.Apply vertical-align: middle; text-align: left; to match standard datasheet typography.
### 6.3 Cell-Level Text Autofit & Wrap Prevention

Execution Logic: During user editing or initial AI rendering, if the translated text inside a cell wraps into multiple lines and exceeds the cell's physical height ($y_1 - y_0$):Trigger an aggressive font-reduction loop specific to tables: automatically downsize the font by 0.5pt increments until the text fits onto a single line or completely fits within the cell boundaries.Minimum font safety cutoff for tables: 7pt. If it still overflows, apply CSS white-space: nowrap; text-overflow: ellipsis; overflow: hidden; and attach a tooltip containing the full text to preserve visual layout sanity.

## 7. Industrial Datasheet UI/UX Specification (Engineering-Grade Workspace)

### 7.1 Entity-Property Decoupled Interaction (Anti-Micro-Clicking)
* **Constraint:** The frontend MUST NOT force users to edit micro-text directly on the canvas. Implement a decoupled Master-Detail layout.
* **Canvas Layer:** Render the PDF using canvas. Overlay a non-editable HTML high-light layer. When a text rect is hovered, draw a bounding box outline.
* **Property Panel Layer:** Implement a sticky sidebar data grid (e.g., using ag-Grid or standard tables). Each row represents a text block entity linked by `block_id`.
* **Sync Mechanism:** Clicking a row in the data grid MUST automatically center and highlight the corresponding `rect` on the canvas viewport. Editing text in the grid inputs must instantly update the temporary canvas rendering text state.

### 7.2 Strict Unit and Symbol Whitelist (Safety Lock)
Industrial semiconductor data sheets cannot tolerate numerical or unit truncation.
* **Frontend Validator:** For fields parsed as electrical specs, parameters, or tolerances (e.g., matching Regex `\d+\s*(V|mA|µA|°C|MHz|Ω)`), the input component must activate a strict validation lock:
  * **Rule:** If the user accidental deletes the unit (e.g., changing "3.3V" to "3.3"), the input field turns red, blocks the update save, and prompts: "Warning: Engineering unit missing."
  * **Overrun Prevention:** If font auto-downsizing hits the minimum threshold (`7pt`) inside a pin-header or ball-grid array map, the system must trigger an immediate modal popup blocking the compilation, forcing either translation truncation or page layout geometric manual override.

## 9. Multilingual Character Set & Font Injection Protocol

### 9.1 Dynamic Font Overriding Engine (Global Fallback)
The backend MUST NOT use the PDF's original embedded fonts for drawing translated text, as they lack the required glyphs for target languages (e.g., CJK characters or specific technical Greek symbols like `Ω`, `µ`).
* **System Map:** Establish a strict Target-Language-to-Font routing table within the backend configuration:
  * `zh` (Chinese): Inject **Noto Sans CJK SC** or **Source Han Sans** (TrueType/OpenType).
  * `de/es/fr` (European): Inject **Liberation Sans** or Standard **Arial** with full Latin-Extended-A support.
  * `ja` (Japanese): Inject **Noto Sans CJK JP**.
* **PyMuPDF Implementation Constraint:** Before executing `page.insert_textbox()`, the backend must explicitly register the external font file via `doc.add_font()` or `page.insert_font()`. Never use the default PDF "Standard 14" fonts (like `helv`, `times`) for multi-language backfilling.

### 9.2 Mixed-Character String Splitting & Universal Typeface Stack
Industrial datasheets often contain mixed strings like `"Max 50V @ 25°C 模拟输入电流"`. A pure Chinese font might render English symbols poorly, while a Western font will choke on Chinese.
* **Agent Execution Rule:** If the target language contains mixed character sets, instruct the rendering script to use a **Pan-Unicode Composite Font** (such as Google Noto Sans Universal) that natively encapsulates Western typography, technical metrics, and Asian glyphs within a single font file.
* **Alternative Tokenizer (Optional):** If a universal font is unavailable, implement an automated string tokenizer that splits the text block into `[Latin]` and `[Non-Latin]` arrays, rendering them sequentially using their respective coordinate offsets and matched fonts.

### 9.3 Font Subsetting to Prevent File Explosion (Optimization)
Embedding a full CJK (Chinese-Japanese-Korean) font package into every processed PDF will cause the output file size to explode (e.g., a 2MB datasheet ballooning into 40MB).
* **Font Subsetting Core:** The backend pipeline MUST enforce font subsetting.
* **Mechanism:** When invoking `PyMuPDF` to embed the external `.ttf` or `.otf` font, ensure the `embedding` parameter is set to subset mode (`font.is_embedded = True` or using `PyMuPDF`'s built-in subset engine). This ensures that *only* the specific character glyphs used in the text are compressed and injected into the target PDF structure.

### 9.4 UTF-8 Normalization Pre-flight Check
* **Rule:** Before any string is sent to the coordinate writing array, pass it through a strict Unicode Normalization wrapper (Python `unicodedata.normalize('NFKC', text)`). This converts full-width alphanumeric anomalies and rogue technical ligatures into standard, globally compatible Unicode code points.

* **Logic:** If `target_language == 'ja'`, the table rendering engine must compress full-width Japanese punctuation marks to half-width equivalents (`font-variant-east-asian: ruby;` in HTML, or custom tracking logic in PyMuPDF) when rendering inside table cells with width $< 80px$.

* **Logic:** If `target_language == 'ko'`, the strict boundary box algorithm must automatically inject a native negative text-margin/letter-spacing asset to prevent adjacent Korean syllables from visual overlapping inside high-density PCB pinout annotations.

If vertical space overflows $H_{max}$, the algorithm must step-down font size by `0.8pt` iterations instead of the standard `0.5pt` to rapidly handle the string expansion.
